# 제공 기체 사양을 구현에 적용하는 기준

2026-10-04. 사용자가 제공 기체의 흑백 320 × 320 영상과 제조사 성능·표준 장착을 그대로 사용하도록 재확인했다.
이는 흑백 변환·해상도·기체 업그레이드를 선택하는 실험 옵션이 아니다.
고정 조건과 미확정 항목은 [provided-hardware.json](../config/provided-hardware.json), 공식 근거는 [제조사 사양](manufacturer-specs.md)에 기록한다.

## 확인된 차이

| 항목 | 제공 하드웨어 기준 | 기존 공유 SIL 기준 |
| --- | --- | --- |
| 영상 | 흑백 320 × 320 고정, ROS 입력 `mono8` | 기본 흑백 324 × 244 |
| 광학값 | 공식 단색 모듈의 공칭 수평/수직 87° | `cf2x_P250` 카메라 수직 70° |
| 질량 | 표준 2.1 단독 29 g; 덱 포함 완성 질량 미확정 | 실행 모델 31.8 g |
| 관성·추진 응답 | 이 장착 구성에 적용할 제조사 근거 미확정 | 제3자 `params.toml` 값 |
| 카메라→기체 장착 변환 | 기본 장착 유지, 수치 미확정 | 위치 `(0.03, 0, 0)` m, 모델 정의 회전 |

31.8 g을 29 g이나 35 g으로 바꾸는 것만으로 제공 기체 모델이 되지 않는다.
35 g은 조건부 AI-deck 1.1/Flow v2 문서 질량의 단순 합이며 완성 기체의 확정 이륙 질량이 아니다.
모델 XML의 원래 질량 27 g도 런타임에 `params.toml`의 31.8 g으로 덮어쓴다.
카메라 위치·관성·모터 응답을 이 모델에서 가져와 제공 기체의 값으로 채택하지 않는다.
[실제 소스에서 추출한 감사 결과](../artifacts/hardware-audit.json).

## 반영한 내용

`scripts/provided_hardware.py`는 새 영상 경로에서 **320 × 320, mono8**을 검사한다.
컬러, 324 × 244, 축소 영상, 잘못된 행 길이·데이터 길이를 거부한다.
ROS 행 padding은 데이터 행에서 제외할 수 있지만 영상 resize나 컬러→흑백 변환으로 형식을 맞추지 않는다.
MuJoCo의 합성 렌더링은 처음부터 320 × 320 크기의 단색 센서 출력 배열로 내보낸다.
이는 제공 기체에 컬러 카메라가 있다고 가정하는 것이 아니다.

새 `moving_landing_scene.py`는 기체 모델을 포함하지 않는 카메라 광학점 장면만 생성한다.
공칭 시야각으로 만든 이상적 투영을 쓰며 실제 보정 행렬·왜곡·카메라 장착 위치를 채우지 않는다.
`moving_landing_core.py`의 기체 좌표 변환은 미확정/공유 모델 장착값을 받으면 실패하도록 했다.
이 파일과 `moving-landing.json`의 추종·하강 제어 수치는 아직 검증하지 않은 설계 초안이다.
제조사 모델이 미확정인 상태를 통과시켜 제공 기체의 동역학·착륙 성능 결과를 생성하지 않는다.

## 실행과 결과

```bash
bash ./scripts/run_provided_camera_check.sh
```

기체 펌웨어·모터 명령 없이 다음을 확인하며, 실행한 프로세스만 종료한다.

- 입력 계약 및 미확정 기체 모델/장착값 거부 **11개 검사 통과**.
- 임시 15 cm 깃발 마커와 30 × 30 cm 상판, 지정 카메라 광학점 40조건에서 **40/40 검출·크기·화면 경계 검사 통과**.
- 합성 단색 입력 → 기존 UDP 카메라 청크 → 공유 CPX → 공유 ROS 영상 브리지 → 입력 검사 → ArUco 경로에서 **60/60 프레임 수신·검출**.
- 실제 ROS 메시지: **320 × 320, mono8, step 320, 102,400 bytes**. 테스트 송신 주기 20fps에서 수신 약 20fps이며 실물 카메라 스트림 성능을 뜻하지 않는다.

실행 결과는 [20261004-181101-897427](../artifacts/provided-camera/20261004-181101-897427/),
상세 [입력·기하 검사](../artifacts/provided-camera/20261004-181101-897427/verification.json),
[ROS 영상 전송 결과](../artifacts/provided-camera/20261004-181101-897427/camera-transport.json)를 따른다.
광학점 위치는 시험대에서 지정했고 영상이 이동 경로를 결정하지 않았다.
실제 렌즈 보정, 롤링 셔터·노출·블러·센서 잡음·Wi-Fi 지연·표준 장착, 폐루프 차량 추종·접촉 착륙은 이 시험으로 검증되지 않는다.
종료 SIGINT 이후 공유 영상 브리지 수신 thread의 일부 Traceback이 로그에 남았다.
60프레임 검사 뒤 발생했고 모든 실행 프로세스는 종료 코드 0으로 종료했지만, 잘린 스택으로 원인을 확정하지 않는다.
팀 소스는 변경하지 않았으며 종료 경합 여부는 별도 확인 대상이다.

## 기존 결과와 다음 작업

기존 [정지 yaw SIL 시험](yaw-first-simulation.md)은 공유 모델에서 영상·gyro·ROS 제어 명령을 연동한 기록이다.
그 성공을 제공 기체 성능 검증으로 해석하지 않는다. 기존 데이터와 팀 저장소는 보존한다.
`yaw-static.json`도 324 × 244 공유 기준선 재현용으로 표시했다. 새 제공 카메라 입력 검사에서는 이 형식이 거부된다.

이 320 × 320 입력에서 관측 후보·신뢰도·지연을 보존하는 상대 위치 추정과 카메라 중심 운동학의 폐루프 추종·하강을 후속 구현했다.
[영상 폐루프 실행 기록](optical-landing-implementation.md), [이동 표면 가상센서 벤치](surface-sensor-bench.md)를 따른다.
차량 설정값 0.3 m/s를 쓰는 FF와 영상에서 추정한 속도를 쓰는 FF는 구분한다.
기체 명령 좌표 변환에는 확인된 카메라 보정·표준 장착 변환이 필요하다.
Flow의 이동 표면 상대속도와 ToF 바닥→상판 전환은 가상센서 벤치에서 확인했으며 실제 센서·기체 추정기로의 통합은 남아 있다.
제공 기체 동역학과 실제 접촉 착륙은 미확정 모델 값을 임의로 대입해 완료 처리하지 않는다.

공칭 시야각·유효 픽셀·피사계 심도 출처:
[Bitcraze 단색 카메라 데이터시트](https://www.bitcraze.io/documentation/hardware/ai_deck_mono_camera/ai_deck_mono_camera-datasheet.pdf).
초점 맞춘 대상 거리 35 cm와 피사계 심도 30 cm–무한대도 설계 제약이며 실제 근거리 인식을 보증하지 않는다.

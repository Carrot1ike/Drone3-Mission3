## 검사 조건

동일 Ubuntu22.04/x86_64 PC에, 경로에 공백이 들어간 별도 공유본을 만들었다. 처음에는 이 사본의 `src/`, `build/`, `.venv-mission3`가 모두 없었다. 팀장 저장소 경로만 지정하고 제조사 소스를 실제 다운로드했으며, Python 가상환경과 C 공유 라이브러리를 새로 설치·빌드했다. 기존 환경·바이너리를 복사하지 않았다. 전체29개 명시 패키지 버전과 pip 의존성 검사를 통과했다.

팀 설치의 CMSIS만 링크로 읽는다. 기존 팀 저장소/CMSIS/제조사 체크아웃의 HEAD·추적 파일 상태와 팀 가상환경의 패키지 버전 목록은 설치 전후 동일했다. 같은 설치를 반복 실행하는 검사도 통과했다.

## 검증 한계와 보존 범위

이것은 **같은 PC에서 새 경로·새 의존성으로 실행한 재현 검사**다. 실제 다른 팀원 PC, 운영체제, GPU 드라이버, 인터넷 연결 조건은 검증하지 않았다. Python3.10/Linux x86_64를 현재 지원 범위로 둔다. 시스템 `gcc`, EGL 또는 OSMesa는 기존 팀 설치가 준비해야 하는 의존성이다.

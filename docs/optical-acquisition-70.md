# 70° 출발에서 마커 탐색·정렬·접근·하강

**과거 비교 기록 — 사용자 그림을 잘못 해석한 조건.** 아래 구현은 차량을 정지시켜 놓고 드론이 회전 탐색했다.
사용자가 그림으로 요청한 실제 조건은 위치·시선 고정 대기, 이미 이동하는 차량의 통과, 마커 발견 후 후방 일직선 정렬이다.
현재 기본 실행과 결과는 [대기·통과 수정 기록](optical-passby.md)이다. 아래 시험 수치는 원래 조건의 기록으로 보존한다.

2026-10-04. 사용자가 설명한 **시선 방향과 차량 뒤쪽을 향한 선 사이의 작은 각 70°**를 구현했다.
흑백 320×320 영상으로 마커를 찾아 추적하고, 진행 방향과 횡방향 위치를 맞춘 후 접근·추종·하강한다.
빠른 시험과 공유 CPX/ROS 영상 경로에서 실행했다. 실행 대상은 이상적인 **카메라 광학점 운동학**이다.
제조사 사양의 실제 기체 동역학·이륙·접촉 착륙·장비 지급 기준 통과는 검증하지 않았다.

## 출발 조건의 정확한 뜻

수평면에서 카메라 위치를 D, 차량 뒤쪽 기준점을 R, 카메라 forward heading을 ψ라고 하면
`abs(wrap(ψ - atan2(R.y-D.y, R.x-D.x))) = 70°`다.
차량 진행 방향에 대한 yaw 70°나 차량 옆으로 떨어진 위치각 70°로 해석하지 않는다.

이번 가상 차량의 뒤쪽 기준점 R은 **30×30cm 착륙장 뒤쪽 변의 가운데**로 지정했다.
초기 D=(0, 0.025, 0.50)m, 상판 중심=(0.35, 0, 0.20)m, R=(0.20, 0, 0.20)m이다.
뒤쪽 선의 방위는 약 -7.125°, 초기 optical heading은 약 62.875°여서 작은 각이 70°다.
R과 앞 깃발 마커 중심은 다르다. 마커를 바라보는 각과 뒤쪽 기준선의 각도 구분한다.
카메라→기체 외부 보정값을 정한 것이 아니며 제조사 미확정 항목은 그대로 남겨뒀다.

실험용 수직 마커는 한 변 15cm, 중심은 상판 중심에서 (0.45, 0, 0.15)m이며 뒤쪽을 향한다.
차량·마커 치수와 아래 제어 이득은 가상 실험 설정이다.
제공 기체의 무개조·제조사 장착·단색 320×320 제약은 변경하지 않았다.

**현재 차량은 최초 유효 마커 발견 전까지 정지하고, 발견 시점부터 +X 방향 0.3m/s로 이동한다.**
처음부터 움직이는 차량을 탐색하는 시험과 차량 속도를 영상으로 추정하는 FF는 후속 작업이다.
현재 FF는 알려진 시험 차량 속도 0.3m/s를 사용한다.

## 명령 생성 순서

1. `SEARCH`: 영상에 마커가 없으면 수평 위치와 높이를 유지하고 -12°/s로 회전한다. 35초까지 탐색한다.
2. `ACQUIRE`: 영상에서 마커가 검출되면 마커 방위를 중앙으로 맞춘다. 이때부터 차량 이동을 시작하고 FF로 거리를 유지한다.
3. `ALIGN`: 차량 진행 방향과 heading을 맞춘다. 영상 heading 오차 ±2°를 1초 유지한다.
4. `LINEUP`: 전후 거리를 유지하며 횡방향 오차를 줄인다. 횡오차 ≤1.5cm, 상대 횡속도 ≤2.5cm/s, yaw ≤2°를 신선한 관측으로 1초 유지해야 접근한다.
5. `APPROACH → TRACK`: 수평 명령 `v_cmd = [0.3, 0] + 0.7*e_xy + 0.5*e_dot_xy`로 접근하고 추종 안정 조건을 확인한다.
6. `DESCEND → SETTLE → COMPLETE`: 영상 위치·속도·heading 조건을 만족할 때만 하강한다. COMPLETE는 상판 위 약 3cm의 광학점 안정 확인이다.

ACQUIRE/ALIGN/LINEUP에서는 최초 발견 때의 영상 추정 전후 거리 `e_x_hold`를 저장해
`v_x = 0.3 + 0.7*(e_x-e_x_hold) + 0.5*e_dot_x`로 거리를 유지한다.
LINEUP에서만 횡방향 위치·속도 보정을 켠다. 모든 관측은 영상에서 얻으며 초기 참값 방향을 제어기에 넘기지 않는다.
참값 위치·속도는 종료 후 평가 CSV와 검토 영상의 오른쪽 도식에만 사용한다.

영상 age >150ms이면 하강과 안정 확인을 금지한다. >400ms이면 명령을 정지하고,
**발견 이후** 관측이 2초 끊기면 ABORT한다. 초기 미발견의 35초 탐색 제한과 구분한다.
속도 norm 0.55m/s, 가속도 0.50m/s², yaw rate 최대 15°/s는 가상 제어 실험 설정이다.

편집 가능한 [단계도](diagrams/acquisition-70.mmd)와 [폐루프 제어 블록도](diagrams/optical-landing-control.mmd)를 저장했다.

## 실행 결과

| 조건 | 최초 마커 발견 | 접근 시작 | 가상 하강 완료 조건 | 결과 |

| 요청한 70°, 빠른 영상 폐루프 | 2.32s | 9.76s | 26.08s | 내부 운동학 검사 통과 |
| 반대쪽 70°, 같은 -12°/s 탐색 | 20.66s | 28.66s | 45.00s | 내부 운동학 검사 통과 |
| 요청한 70°, CPX/ROS 경로 | 2.343s | 9.963s | 26.503s | 내부 운동학 검사 통과 |
| 마커 없는 단색 영상 | 미발견 | 진입 없음 | 35.00s ABORT | 예상한 탐색 제한 종료 통과 |

같은 회전 방향을 사용하므로 반대쪽에서는 한 바퀴 가까이 돌며 탐색 시간이 길어진다.
모든 각도·거리·이동 속도에 대응한다는 검증은 아니다. 추후 탐색 방향 전략을 비교할 수 있다.

ROS 단계 전이는 ACQUIRE 2.343s → ALIGN 6.143s → LINEUP 7.963s → APPROACH 9.963s
→ TRACK 14.783s → DESCEND 16.803s → SETTLE 26.183s → COMPLETE 26.503s였다.
접근 시작 시 종료 후 참값 횡오차는 약 1.09cm, heading은 약 -0.022°였다.
종료 전 1초의 광학점 중심 오차 최대 약 1.46mm, 상대 수평 속도 최대 약 2.29mm/s,
높이 범위 약 3.62–4.08cm다. 이상적 명령 추종·투영으로 얻은 값이며 실기체 정밀도 수치가 아니다.
마지막 기록의 optical height는 약 3.61cm다. 상판에 닿은 결과가 아니다.

마커 없는 시험은 실제 검출기에 전 프레임 단색 입력을 넣었고 `marker_missing`만 기록했다.
최초 영상 미검출, SEARCH 중 위치 유지, 발견 즉시 ACQUIRE 전이, LINEUP 조건 1초 유지 후 접근,
미발견 시 하강하지 않음을 [종료 후 추가 평가](../artifacts/optical-acquisition/validation-summary.json)로 확인했다.
기존 제어 계약 검사 7개와 새 탐색 계약 검사 3개도 통과했다.

재생 시각·코드 해시는 각 실행의 `review-metadata.json`에 기록했다.

## 재실행

```bash
# 공유 ROS 영상 경로와 동일 관측/제어 모듈
bash ./scripts/run_optical_landing_ros.sh --scenario rear-bearing70

# 빠른 영상 폐루프, 반대쪽 조건, 미발견 중단 시험
bash ./scripts/run_optical_landing.sh --scenario rear-bearing70
bash ./scripts/run_optical_landing.sh --scenario rear-bearing-minus70
bash ./scripts/run_optical_landing.sh --scenario blind-search
```

설정은 `config/optical-acquisition-70.json`, 조건 생성은 `scripts/optical_landing_scenarios.py`,
제어 변경은 `scripts/landing_mission.py`, 계약 검사는 `scripts/verify_acquisition_70.py`다.
`scripts/evaluate_acquisition_70.py <실행 결과 폴더들>`로 단계 조건을 다시 평가할 수 있다.
결과·설정·코드 해시는 실행별 새 폴더로 보존했다. 팀 공유 원본 저장소와 외부 인터넷 자료는 변경하지 않았다.

## 남은 착륙 작업

제조사 근거의 장착 변환·카메라 보정·조립 기체 동역학을 확인한 뒤 실제 기체 setpoint adapter와 연결해야 한다.
움직이는 상판으로 Flow/ToF가 전환되는 조건, 기체 자세 변화와 영상 시야, 충돌·접촉·모터 종료는 별도 검증이 필요하다.
현재 실행의 명령은 `/drone3/optical/cmd_velocity`이며 가상 광학점만 구동한다.
전체 후속 작업은 [기존 구현 문서](optical-landing-implementation.md)의 미완료 항목을 따른다.

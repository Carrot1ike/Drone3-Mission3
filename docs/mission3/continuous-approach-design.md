# 접근을 연속적으로 만드는 제어 구조

대기·인식·정렬·접근·착륙의 단계는 유지한다. 단계가 바뀔 때 하위 자세 PID나 추정기를 초기화하지 않고, 정렬 확인 뒤 이동 거리와 높이 목표를 함께 변화시키는 reference를 상위 속도 제어에 넣는다. 편집 가능한 [간단 도식](../diagrams/mission3-continuous-approach-candidate.mmd)은 실험 후보를 설명한다.

상위 속도 명령은 `추정 차량 속도 + 접근 목표의 변화 속도 + 상대 위치·속도 오차 보정`이다. 차량 위치·속도 truth는 종료 후 평가에만 쓴다. 같은 진행도에 따라 전진과 하강이 이루어져 먼저 내려가고 그 높이에서 따로 전진하는 경로를 줄인다. 속도·가속도·yaw·상하 속도의 기존 포화는 출력 단계에 남긴다. 목표의 quintic 시간 함수는 위치·속도·가속도가 양 끝에서 연속이라는 수학적 성질을 가지지만, noisy feedback나 실제 기체의 jerk까지 제한하는 구현은 아니다.

센서 신뢰도 확인을 생략하지 않는다. v22 후보는 마지막 reference 구간에서 높이·횡방향 오차가 기존 범위 안에 머무르는 1초를 누적한다. 경로가 완료되고 그 확인도 통과해야 다음 단계로 넘어간다. 범위를 벗어나면 확인 시간을 초기화한다. reference가 끝난 뒤 별도로 1초를 기다릴 필요가 없는 경우를 다루는 것이다. TRACK의 2초와 영상 크기·초점·직선 여유·Flow/ToF·불확실성·terminal 예측 제한은 그대로 유지한다.

마커를 잃거나 실제 Flow 관측 표면이 바뀌는 동안 계속 하강하도록 강제하면 작은 이동 패드에 대한 근거를 잃는다. 현재의 목표는 불필요한 정지 시간을 줄이면서 정확도를 보존하는 것이며, 모든 조건에서 무정지 하강을 보장하는 것이 아니다. v21에서는 두 조건부 접촉을 유지했지만 정지 감소/착지 오차의 사전 비교 기준을 동시에 통과하지 못했다. 그 결과와 v22 시험은 [접근 기록](continuous-approach-20261009.md)에 분리한다. 공식 기체 일치와 실기 성공은 아직 0이다.

현재 수학 함수·새 확인 방식·실험 시간·포화 값은 D/S이고 실측 기체 성능이 아니다. [PX4 공식 trajectory 문서](https://docs.px4.io/main/en/config_mc/mc_jerk_limited_type_trajectory)는 reference의 변화율을 제한하는 방식의 근거로 읽었으며, PX4 코드·기체 값·성능을 Crazyflie에 이식하지 않았다. 현 구현은 더 단순한 quintic reference와 기존 slew limiter이다. 다음 연구에서 실제 수평·수직 응답, 영상 가시성, 지연 불확실성, 착지 오차를 함께 비교해야 한다.

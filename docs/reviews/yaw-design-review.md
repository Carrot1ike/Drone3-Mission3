# yaw 보정 설계 통합 검토

검토일: 2026-10-04 (Asia/Seoul).
이 문서는 사용자 요청으로 수행한 하위 에이전트 분석과 parent 검증을 통합한다.
하위 에이전트 두 개의 독립 검토와 parent의 소스 대조·import 재현을 완료했다.
비행 제어나 기체 내부 추정기는 구현하지 않았으며 yaw 폐루프를 실행하지 않았다.

**결론:** 상대 yaw 보정 구조는 조건부로 타당하다. 먼저 정지 마커 기준 기수 방향 유지로
검증 범위를 한정하고, 후보 불확실성·측정 시각·명령 단위/부호·제어권 인계·상실 복구를 명시해야 한다.
초기 정면 배치나 단순한 시간 필터만으로 이 조건이 충족되지는 않는다.

## parent가 대조한 제어 계약

고정 소스에서 firmware protocol은 7이다. 이 경로의 ROS hover 입력 `u`는
`−degrees(u)`로 CFLib에 전달되고, CFLib legacy hover 패킷에서 다시 반전되며,
firmware decoder가 수신값을 다시 반전한다.
따라서 내부 `attitudeRate.yaw = −degrees(u)`다. 이는 **소스상의 목표 변환**이며
물리 회전 방향을 실험으로 확인한 결과는 아니다. protocol이 바뀌면 재검토한다.

PID는 이 값을 적분해 yaw 목표 각도를 갱신한다. `yaw_rate=0`은 그 목표 유지이며,
즉시 실제 회전 정지나 내부 추정 yaw 보정을 의미하지 않는다.

CRTP 목표 수락은 high-level planner를 중단한다. `notify_setpoints_stop`의 로컬 decoder는
유효시간으로 호버를 연장하지 않고 우선순위를 낮춘다. 중단된 planner는 null 목표를 반환할 수 있다.
그러므로 종료/착륙은 명시적 복구 계획과 제어권 전환의 순서를 설계하고 검증해야 한다.
영상이 없어지는 것과 명령 스트림이 끊기는 것을 같은 상황으로 처리하지 않는다.

부호 경로·PID 적분·제어권·Image stamp·gyro 단위는 parent가 agent의 인용 소스와 대조했다.
동적 응답, 종단 지연, 실제 회전 부호, 제어권 전환 성공은 아직 미검증이다.

## parent가 직접 확인한 사항

| 확인한 사실 | 설계에 미치는 영향 |
| --- | --- |
| 기존 기하 기록에 yaw-only 오차는 없다 | 전체 회전 오차를 yaw 보정 정확도로 제시할 수 없음 |
| 작은 재투영 오차와 큰 전체 회전 오차가 함께 나타남 | RMSE만으로 후보의 방향을 신뢰하기 어려움 |
| 기존 detect_pose는 최소 RMSE의 단일 자세 반환, 왜곡 0 | 후보 유지·시간 일관성·실제 보정 파라미터는 추가 구현 필요 |
| 공유 ROS 영상은 324×244, 기존 기하 시험은 이상적 320×320 | 기존 카메라 행렬을 그대로 재사용하지 않음 |
| 공유 ROS 환경의 cv2 import가 NumPy ABI 충돌로 실패 | ArUco node 구현 전 호환 영상 의존성을 준비해야 함 |
| 팀 기본 장면에 ArUco가 없고 IMU noise 옵션은 비활성 | 기본 설치 검사만으로 시각 yaw 보정이나 드리프트 억제 성능을 판정하지 않음 |

직접 재현한 증거는 `artifacts/yaw-design-review/20261004/`에 있다.
기존 기하·센서 수신·새로운 비행 제어의 검증 범위를 구분한다.

## 후속 작업 순서

권장 검증 순서는 [yaw-verification-plan.md](yaw-verification-plan.md)에 정리한다.
추정 오차와 실제 기수 방향 오차를 따로 측정한다.
처음에는 정지 마커를 기준으로 초기 기수 방향을 유지하는 소규모 시험을 제안한다.
그다음 차량 축 정렬·차량 직진 추종을 검증한다.

내부 `stateEstimate.yaw`의 드리프트 보정은 상위 상대 yaw 제어와 구분하여
후속 설계·측정 융합·검증을 수행한다.

## 검토 수행 기록

Opus 5.5 xhigh 두 에이전트는 보고서를 반환하지 않아 실행 중 종료했다.
그 결론은 검토 근거로 사용하지 않았다. 이후 기본 모델을 상속한 두 에이전트
McClintock(관측)·Fermat(명령)로 범위를 좁혀 최종 보고서를 받았고, parent가 위 근거를 대조했다.
완료한 에이전트는 종료했다. 공유 저장소·패키지·펌웨어 설정은 이번 분석에서 변경하지 않았다.

# 이동 차량·수직 마커 시야 및 자세 추정 시험

검증일: 2026-09-30 (Asia/Seoul).

이번 코드는 **차량의 등속 이동, 가상 카메라 광학 중심의 지정 경로, ArUco 검출·자세 추정**을 구현했습니다. 기체 동역학·제어 명령·자율 착륙·접촉은 구현하지 않았습니다. 장비 지급 합격 기준도 아직 정해지지 않았으므로 아래 기준은 이 단계의 내부 회귀 검사입니다.

## 사용자 조건과 값의 출처

- 실기체·Crazyradio는 아직 없으며 시뮬레이션 승인 후 지급 예정입니다.
- 하드웨어 개조는 금지, 소프트웨어 변경은 허용되는 것으로 이해합니다. 실제 지급/운용 규정은 그때 다시 대조합니다.
- 장착은 제조사 안내를 따릅니다. AI-deck는 제조사 안내에서 위/아래 모두 허용하므로 유일한 기본 적층을 임의로 확정하지 않습니다. [장착 검토](mounting-review.md).
- 작업용 조건부 프로필은 표준 Crazyflie 2.1 + AI-deck 1.1 + Flow deck v2입니다. 향후 지급될 데크 버전이 확정된 것은 아닙니다.
- 카메라는 제조사 단색 모듈의 유효 해상도 320 × 320 및 공칭 수직 화각 87°를 사용한 **이상적 핀홀 투영**입니다. 실제 스트리머의 크롭·반전·왜곡·장착 변환·전송 지연을 보정한 카메라 모델이 아닙니다. [공식 모듈 데이터시트](https://www.bitcraze.io/documentation/hardware/ai_deck_mono_camera/ai_deck_mono_camera-datasheet.pdf).

`config/landing.toml`에서 제조사 공개 광학값과 가상 실험 변수를 구분합니다. 마커·차량 치수는 사용자 허용에 따라 설정한 실험값입니다.

| 변수 | 값 | 출처 |
| --- | --- | --- |
| 착륙장 | 30 × 30 cm | 사용자 확정 |
| 차량 속도 | 0.3 m/s, 세계 +X 등속 직진 | 사용자 확정; 영상 추정값 아님 |
| 착륙장 상면 높이 | 지면 위 20 cm | 임시 차량 실험값 |
| ArUco | DICT_4X4_50, ID 0 | 임시 실험값 |
| 마커 한 변 | 10 cm, 검은 외곽 테두리 포함 | 임시 실험값; 흰 여백 제외 |
| 흰 여백 | 각 방향 2 cm, 판 한 변 14 cm | 임시 실험값 |
| 착륙점→마커 중심 | 차량 축에서 (앞 40 cm, 옆 0, 위 15 cm) | 임시 차량 실험값 |
| 마커 방향 | 수직, 정면은 차량 뒤쪽(-X)의 착륙장으로 향함 | 사용자 선택 배치 |

카메라 중심은 착륙점 뒤 40 cm·옆 4 cm·위 25 cm에서 시작합니다. 먼저 가상 yaw와 횡방향 편차를 줄이고, 착륙점 위로 이동한 뒤, 상면 기준 광학 중심 높이를 6 cm까지 낮춥니다. **6 cm는 카메라 시야 시험 높이이며 착륙 접촉 높이 또는 기체 장착 높이가 아닙니다.** 전체 경로 10초를 20 Hz로 샘플링합니다. 20 Hz는 시험 설정이며 제조사 스트리밍 fps가 아닙니다.

## 제어기를 만들기 위한 관측 시험

우리가 설계할 것은 PC의 **상위 착륙 제어기**입니다. 그 제어기는 상대 상태와 단계별 목표에서 매 시점 속도·하강·yaw 목표를 계산하고, 기체의 기존 내부 제어기가 목표를 추종합니다. 단계를 관리하는 것과 오차를 줄이는 피드백 계산은 서로 다른 기능입니다.

이번 시험은 제어기에 들어갈 영상 관측이 가능한지 먼저 확인합니다. 카메라 경로를 직접 지정했으므로, 보이는 정렬·접근·하강은 제어기가 만들어낸 비행 결과가 아닙니다. 다음에는 관측 품질·지연·평면 자세 모호성을 처리하고 상위 제어기를 구현해야 합니다.

## 코드와 관측 입력

- `scripts/landing_scene.py`: MuJoCo의 kinematic mocap 장면. 차량과 카메라만 있으며 기체 모델·모터·관성·추력은 없습니다. 파란 점과 선은 카메라 중심·광축을 표시하는 시각화 기호입니다.
- `scripts/aruco_pose.py`: RGB/회색 영상 → 지정 ID 검출 → IPPE_SQUARE의 복수 자세 후보 → LM 정밀화 → 양의 깊이·최소 재투영 오차 해 선택.
- `scripts/preview_landing.py`: 경로 샘플링, 검출·자세 오차 검사, 시야 이탈 음성 사례, 결과 그림·JSON 저장. 카메라에서 추정한 마커→착륙점 고정 변환을 회전과 함께 적용합니다.

검출기는 영상·명목 투영 행렬·마커 사전/ID·10 cm 크기만 받습니다. 착륙점 변환에는 고정된 마커 배치를 사용합니다. 시뮬레이터의 위치·자세 참값은 검출기 입력에 넣지 않고 **기하·오차 평가에만 사용**합니다. 기체↔카메라 변환은 미확정으로 유지하며, 0이라고 가정하지 않습니다.

| 마커의 가장 짧은 투영 변 길이 최솟값 | 약 21.05 px |
| 착륙점 부근의 광학 중심 위치에서 검출 | 118 / 118 프레임 |
| 그 구간의 착륙점 상대 위치 오차 최댓값 | 약 **1.83 cm** |
| 전체 경로의 착륙점 상대 위치 오차 최댓값 | 약 **14.59 cm**, 먼 구간 |
| 재투영 오차 최댓값 | 약 0.261 px |
| 과도한 높이(상면 위 80 cm)의 시야 이탈 사례 | 마커 모서리가 시야 밖, 미검출 확인 |
| GUI | 10초 경로 실행·정상 종료 확인 |

여기서 “착륙점 부근”은 **평가 참값으로 광학 중심의 수평 위치가 착륙장 중심에서 8 cm 이내**인 샘플입니다. 이 조건을 제어기의 단계 전환 판단에 참값으로 제공하지 않았습니다.

내부 기준은 전체 검출률 95% 이상, 근접 구간 전 프레임 검출·상대 위치 오차 4 cm 이하, 재투영 오차 1.5 px 이하, 계획한 높은 카메라의 미검출과 차량의 지정 이동 거리 일치입니다. 검사 기준은 첫 실행 전에 설정했고 변경하지 않았습니다. 첫 IPPE-only 실행에서는 근접 오차가 약 20.75 cm라서 실패했습니다. 두 자세 후보를 관측 모서리로 LM 정밀화한 뒤 근접 오차가 약 1.83 cm로 줄어 동일 기준을 통과했습니다.

**전체 위치 추정 정확도가 착륙 수준으로 검증된 것은 아닙니다.** 먼 구간은 마커가 작고 평면 자세의 모호성이 있어 약 14.59 cm 오차가 남습니다. 낮은 재투영 오차만으로 착륙점 정확도를 보장하지 않으므로, 실제 제어에는 관측 이력·자세 제약·품질 검사와 정렬/접근 단계별 처리 설계가 필요합니다. 검출률은 이 명목 경로의 이상적 영상 결과이며 다양한 환경의 검출 성공률이 아닙니다.

## 실행

이미지와 검증 JSON을 만드는 기본 실행:

```bash
bash ./scripts/preview_landing.sh
```

MuJoCo 창에서 경로를 10초 동안 표시:

```bash
bash ./scripts/preview_landing.sh --gui
```

창을 닫거나 Ctrl+C를 누르면 종료합니다. 이 프로그램은 펌웨어·UDP·Crazyradio에 연결하지 않습니다. 자세 추정 모듈의 별도 수치·단위 확인:

```bash
./.venv/bin/python -B ./scripts/aruco_pose.py
```

최신 결과는 `artifacts/landing-visibility.json`과 `.png`이며, 실행별 원본은 `artifacts/visibility/<KST 실행 시각>/`에 보존합니다. JSON에는 `autonomous_controller_implemented=false`, `aircraft_dynamics_validated=false`, `touchdown_validated=false`, `equipment_acceptance_passed=null`을 명시합니다. 자동 착륙 성능이나 장비 지급 통과로 해석하지 않습니다.

다음 검증은 먼 구간 자세 모호성·시간 필터와 관측 손실을 먼저 처리한 뒤, 정지 표적의 폐루프 정렬·접근입니다. 제조사 기반 동역학 모델의 미확정 항목과 이동 표면 Flow/ToF 처리는 별도로 해결해야 합니다.

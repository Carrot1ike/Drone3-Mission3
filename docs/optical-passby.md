# 고정 대기 → 지나가는 차량 인식 → 일직선 정렬 → 접근·하강

2026-10-04. 사용자가 첨부한 ①~④ 그림에 따라 시나리오를 수정했다.
드론은 위치·시선을 고정한 상태로 대기한다. 차량은 이미 움직이고 있으며,
시야에 들어온 ArUco를 인식한 뒤 드론이 차량 뒤쪽으로 이동해 일직선 정렬하고 접근·추종·하강한다.
이전의 정지 차량·회전 탐색은 잘못 해석한 조건이며 [과거 기록](optical-acquisition-70.md)으로 보존했다.
사용자 원본 그림은 [①~②](../assets/reference/passby/user-sketch-1.png), [③~④](../assets/reference/passby/user-sketch-2.png)에 복사해 보존했다.

현재 실행 대상은 카메라 광학점의 이상적 운동학이다. 실제 기체 이륙·물리 접촉 착륙은 아직 검증하지 않았다.
무개조 Crazyflie 2.1 + AI-deck + Flow deck, 제조사 장착, 본래 단색 320×320 조건은 유지한다.
미공개 장착·보정·관성·추진 값을 외부 모델로 채우지 않았다.

## 그림에 대응하는 명령

| 사용자 그림 | 구현 단계 | 생성하는 명령 |
| --- | --- | --- |
| ① 대기, 차량 이동 | `WAIT` | 속도 3축 0, yaw rate 0. 차량은 독립적으로 0.3m/s 이동 |
| ② 지나오는 마커 발견 | `ACQUIRE` | 영상 마커 중심으로 yaw 보정, 차량 속도 FF로 상대 전후 거리 유지 |
| ③ 마커와 일직선 | `LINEUP → APPROACH` | 마커를 계속 바라보며 후방 대기점으로 이동하고 횡방향·yaw를 맞춘 뒤 접근 |
| ④ 착륙 | `TRACK → DESCEND → SETTLE` | 추종 안정 확인 후 하강. 현재 완료는 가상 광학점의 상판 위 근접 안정 확인 |

마커가 보인 순간 yaw만 차량 진행 방향으로 돌리면 아직 옆에 있는 마커가 시야 밖으로 나갈 수 있다.
따라서 LINEUP 중에는 **마커를 바라보는 yaw와 후방·횡방향 이동을 함께 계산**한다.
마커 방위 오차가 커질수록 후방 대기점으로 가는 위치 보정을 줄여 시야를 유지한다.
이는 실제 카메라 외부 보정이나 roll/pitch 보장을 확정한 것이 아닌 가상 광학점의 제어 방식이다.

가상 후방 대기점은 상판 중심에서 진행 방향 뒤로 35cm다. 횡오차 ≤1.5cm,
전후 거리 오차 ≤2.5cm, 두 상대 수평 속도 성분 각각 ≤2.5cm/s,
yaw 오차 ≤2°를 신선한 영상으로 1초 유지해야 APPROACH로 전환한다.
상판 바로 위로 접근하기 전에 후방 일직선 정렬을 확인한다.

수평 FF는 알려진 실험 차량 속도 `[0.3, 0]`이며 영상으로 차량 절대 속도를 추정한 값은 아니다.
접근 이후 수평 명령은 `v_cmd = [0.3, 0] + 0.7*e_xy + 0.5*e_dot_xy`다.
LINEUP에서는 전후 목표를 상판 중심이 아닌 후방 35cm로 두고 마커 방위 기반 이동 제한을 추가한다.
제어기는 차량 시작 요청을 보내지 않는다. 차량 참값은 종료 후 평가에만 사용한다.

## 장면·시계 설정

상판 30×30cm, 상판 높이 20cm, 임시 수직 마커 한 변 15cm,
마커 중심의 상판 오프셋 (0.45, 0, 0.15)m, 차량 0.3m/s +X 직진이다.
광학점은 (0, -0.35, 0.50)m에서 heading 90°로 대기한다.
뒤쪽 기준점은 상판 뒤쪽 변의 가운데 (-0.961617, 0, 0.20)m이다.
초기 시선 90°와 이 기준점으로 향한 선의 방위 160° 사이 작은 각이 **70°**다.
이 수치는 실험 장면의 가상 위치·방향이며 실제 AI-deck 장착값이나 기체 사양이 아니다.

오프라인에서는 t=0부터 차량이 움직인다. ROS에서는 통신·프로세스 준비 시간을 제외하기 위해
첫 WAIT 명령 수신을 임무 시계 시작으로 사용하고, 이후 차량은 관측·명령 유실 여부와 관계없이 계속 이동한다.
ArUco 발견이나 `/drone3/optical/vehicle_start`는 차량 시작 조건이 아니다.
현재 시험은 가상 광학점이 이미 대기 높이에 있는 상태에서 시작하며 기체 이륙 단계는 포함하지 않는다.

대기 중 광학점 위치·heading 변화는 두 명목 실행 모두 0이었다.
발견 직전 차량은 오프라인 약 48cm, ROS 약 44.4cm를 이동했다.
각 기록의 시간 차와 차량 이동량을 대조해 0.3m/s 이동이 전 구간 유지됨을 확인했고,
모든 제어 명령의 차량 시작 요청이 False임도 확인했다.
APPROACH 전 1초 전체가 위 정렬 조건을 충족했다.
ROS 접근 시작 시 종료 후 참값은 후방 거리 약 34.0cm, 횡오차 약 1.00cm, heading 약 -0.051°였다.

ROS 종료 전 1초의 최대 중심 오차 약 1.76mm, 상대 수평 속도 약 2.37mm/s,
광학점 높이 범위 약 3.62–4.05cm였다. 이상적 운동학·투영의 수치이며 실기체 정밀도가 아니다.
마지막 기록은 상판 위 약 3.61cm다. 접촉 착륙이나 모터 종료 성공으로 기록하지 않는다.
차량 총 이동은 ROS 약 11.77m, 오프라인 약 12.34m로, 실제 시험장 길이는 별도 확인이 필요하다.

마커 없는 경우에도 차량은 35초 동안 10.5m 이동했다. 드론은 회전·병진 없이 대기하다가 ABORT했고 접근·하강하지 않았다.
순수 제어 계약 검사 기존 7개, 과거 회전 탐색 회귀 3개, 새 대기·정렬·손실 검사 5개를 통과했다.
[종료 후 통과 조건 검사](../artifacts/optical-passby/validation-summary.json)를 저장했다.

실제 보정·왜곡·노출·blur·장착 오프셋은 미확정이다.
ROS 재생은 관측 수신 시각에 맞춰 다음 관측까지 직전 프레임을 유지하며, 입력 해상도는 변경하지 않는다.

## 재실행

기본 시나리오를 이번 `passby70`으로 바꿨다.

```bash
bash ./scripts/run_optical_landing_ros.sh

# 같은 조건의 빠른 영상 폐루프
bash ./scripts/run_optical_landing.sh --scenario passby70

# 차량이 지나가도 마커가 안 보이면 대기 유지·중단
bash ./scripts/run_optical_landing.sh --scenario passby-no-marker
```

설정 `config/optical-passby.json`, 조건 생성 `scripts/optical_landing_scenarios.py`,
상태기계 `scripts/landing_mission.py`, 계약 검사 `scripts/verify_passby.py`,
종료 후 검사 `scripts/evaluate_passby.py`를 추가·수정했다.
결과·원본 설정·코드 해시는 실행별 폴더에 보존했다. 외부 저장소·인터넷 자료는 변경하지 않았다.

제조사 자료의 카메라 보정·표준 장착 변환·조립 기체 동역학을 확인한 뒤 실제 기체 명령으로 연결해야 한다.
움직이는 상판의 Flow/ToF 전환, 기체 자세와 마커 시야, 충돌·접촉·모터 종료는 미완료다.
이 명령은 `/drone3/optical/cmd_velocity`의 가상 광학점만 움직인다.
